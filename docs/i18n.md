# Internationalisation

The app ships **en-US and ko-KR**, wired with [intlayer](https://intlayer.org).

Every user-facing string lives in a `*.content.ts` dictionary and is read by
key. Where those strings live and how they are written is
[ux/copy.md](ux/copy.md); how dates, numbers and direction are rendered is
[l10n.md](l10n.md). This file is the wiring.

## The shape

```ts
// apps/web/src/pages/items/items.content.ts
import { type Dictionary, insert, t } from "intlayer";

export default {
	key: "items",
	content: {
		title: t({ "en-US": "Items", "ko-KR": "품목" }),
		range: insert(
			t({
				"en-US": "{{from}}–{{to}} of {{total}}",
				"ko-KR": "총 {{total}}개 중 {{from}}–{{to}}",
			}),
		),
	},
} satisfies Dictionary;
```

```tsx
const c = useIntlayer("items");
<h1>{c.title}</h1>
<p>{c.range({ from, to, total })}</p>
<input placeholder={c.searchPlaceholder.value} />
```

`.value` for anything that is not rendered — `toast()`, `aria-*`,
`placeholder`, a zod message. The shape table in [ux/copy.md](ux/copy.md) is
the reference.

**Outside a render**, use `getIntlayer(key, locale)`. A route's `head` is
computed by the router and a scenario test never mounts a provider, so neither
can call a hook:

```ts
head: () => ({
	meta: [{ title: documentTitle(getIntlayer("items", currentLocale()).title) }],
}),
```

## Where the locale lives

`apps/web/src/shared/lib/locale/locale-store.ts` is the source of truth, and
`IntlayerProvider` is **told** — it does not detect or persist on its own.
Letting it do so would give two stores that disagree the first time someone
clears localStorage but not the cookie, and the one the transport reads would
not be the one the UI renders.

The store is in `shared/` for the reason `theme-store.ts` gives for the same
choice: `shared/api/transport.ts` needs it to stamp `Accept-Language`, and a
lower layer importing from `app` is the FSD direction reversed.
`app/providers/locale-provider.tsx` keeps only the React component that applies
it — `<html lang>`, `<html dir>`, `IntlayerProvider` and Radix's
`DirectionProvider`.

Detection matches on the **primary subtag**: a browser asking for `en-GB`
resolves to `en-US`. Comparing whole tags is how a negotiator quietly serves
everyone the default.

## Switching

`shared/ui/locale-toggle.tsx`, rendered by the app shell AND by the sign-in
page. That second placement is the point: a switcher that only exists behind
authentication is unreachable to the person most likely to need it, and the
sign-in screen is where someone who cannot read the interface arrives first.

Each label is written **in the language it offers** — "한국어로 전환" on an
English page. "Switch to Korean" is readable by everyone except the person it
is for.

## Server text

A definite failure's message is rendered verbatim — `toUserMessage` returns
`error.rawMessage`, `extractFieldErrors` puts it on a field — and no client
dictionary can translate an arbitrary sentence.

So the client states its preference: `acceptLanguageInterceptor` stamps every
request with the current locale, read through a **thunk** so a language switch
takes effect without rebuilding the transport. Answering in that language is
the server's half of the contract, and a server that ignores the header shows
English errors on a Korean page.

The indeterminate path needs nothing: `toUserMessage(error, fallback)` takes
its fallback from the call site's dictionary, so network failures, timeouts and
aborts — most of what a user actually sees — are already localised.

**Do not add a client-side `Code` → message map.** It duplicates the server's
taxonomy where it drifts, and ConnectRPC's codes are far too coarse to carry a
useful sentence: every validation failure is `InvalidArgument`. If a server can
emit a stable machine-readable code in `details`, a dictionary keyed on THAT is
correct, and `field-errors.ts`'s `fromDetails` is already the seam.

## Routing

The locale is **not in the URL**. Store only.

The cost is real and worth stating: a shared link does not carry the language,
so a Korean user pasting `/items?status=active` to a colleague shows it in the
colleague's language, and there are no per-locale URLs for a crawler.

The cost of the alternative is higher today. A `$locale` root param moves every
route under it and regenerates `routeTree.gen.ts` wholesale; every `Link`
gains a `params`, so `NAV_ITEMS` can no longer be a module-scope constant and
`linkOptions`' entire value — type-checking at the declaration — is lost. Worst,
`safe-redirect.ts`'s `HOME = "/"` becomes a function of state, and that module's
one job is that exactly one place constructs a `SafeRedirect`.

**Add it when** the app is public and indexed, or when support needs to
reproduce a report in the reporter's language.

## Traps

- **Content functions run at BUILD TIME with no arguments.** A
  `(name: string) => string` inside a dictionary is not an interpolator — it is
  a value computed once and frozen. Use `insert()` with named placeholders.
- **The Vite plugin stays ON under Vitest; the WATCHER is what goes off.**
  `app/router.test.tsx` renders the real route tree, so every screen calls
  `useIntlayer`; without the plugin those imports do not resolve and the test
  dies before its first assertion. The watcher is `content.watch` in
  `intlayer.config.ts`, and left on it keeps the Node process alive after the
  last assertion — which reads as a hang, not a failure.
- **`.intlayer/` is generated and gitignored, and `tsc` runs no codegen.** A
  fresh clone would type-check red on keys that are perfectly valid, and only
  on a machine that has never run the dev server. `apps/web`'s
  `pretype:check: intlayer build` is what closes that — and it matters because
  CI runs `pnpm install --frozen-lockfile` and then `pnpm type:check` with
  nothing in between.
- **`export default` in a `*.content.ts`** is the one carve-out to "named
  exports only". The CLI reads the default export; there is no named form.
- **The three packages move together**, in `pnpm-workspace.yaml`'s `catalog:`.
  `vite-intlayer` generates the `.d.ts` augmentation `react-intlayer` reads; a
  skew is a type error on a key that exists.
- **No Vite alias.** The plugin injects the resolution and the generated types
  cover tsc, so the "an alias must appear in three places" rule does not apply.
  Adding one would be actively harmful: Vite matches by prefix, so `"intlayer"`
  would also swallow `intlayer/routing`.
- **`strictMode: "strict"`** makes a missing `ko-KR` a type error. Under the
  default `"inclusive"` it is a warning and renders the English, which looks
  exactly like a string translated to the same word.

## Adding a locale

1. Add it to `intlayer.config.ts`'s `locales` and to `LOCALES` in
   `locale-store.ts` — the two must match, or a persisted tag the provider does
   not declare falls back to the default on every reload, silently.
2. `pnpm type:check`. `strictMode: "strict"` lists every entry that is missing
   it.
3. If it is right-to-left, read the RTL section of [l10n.md](l10n.md) first:
   `<html dir>` and `DirectionProvider` are already wired, but
   `packages/design/src/ui/primitive/` still uses physical direction utilities.
