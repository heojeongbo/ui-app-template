# Internationalisation

The template ships the **pattern**, not the library.

Every screen's strings live in a `*.content.ts` module rather than inline in
JSX — see [ux/copy.md](ux/copy.md). That separation is the part that matters,
and it is worth having even in a single-language app: the page component
becomes pure rendering, and a scenario test can assert against the same strings
the UI shows.

## Adding a library

Because the strings are already isolated, adopting one is a change to the
content modules and nothing else.

With **intlayer** (the convention this template's conventions were drawn from),
a content module becomes a dictionary:

```ts
export default {
  key: "items",
  content: {
    title: t({ en: "Items", ko: "품목" }),
  },
} satisfies Dictionary
```

and the page reads `useIntlayer("items")`.

Two things to get right when you do:

1. **`.value` for anything that is not rendered.** An intlayer leaf is
   `ReactNode & { value: T }`. `toast()`, `aria-*`, `placeholder` and zod
   messages need the raw string. See the shape table in
   [ux/copy.md](ux/copy.md).

2. **The cold-checkout trap.** `.intlayer/` holds generated dictionary types, is
   gitignored, and is produced only by the Vite plugin — while `type:check` is a
   bare `tsc` that runs no codegen. A fresh clone therefore fails type-check on
   every `useIntlayer` key until a build has run once. Add an `intlayer build`
   as a `pretype:check` step so the trap cannot happen, and skip the plugin
   under `VITEST` or its watcher holds the test run open for the full close
   timeout.

## Why it is not wired up by default

It is a real dependency with a real codegen step, and a template that ships it
unused costs every consumer that decision. The separation it depends on is
already here; turning it on is a small, local change.
