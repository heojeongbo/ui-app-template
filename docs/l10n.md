# Locale-sensitive rendering

Dates, numbers, sorting, direction and type. [i18n.md](i18n.md) covers the
words; this covers everything else that changes with the language.

## The formatting seam

`apps/web/src/shared/lib/format/` — `useFormatters()` in a component,
`createFormatters(locale)` anywhere else.

It exposes a **closed set of named presets**, not an options object:

| Preset | `en-US` | `ko-KR` |
| --- | --- | --- |
| `date` | `Jan 1, 2026` | `2026. 1. 1.` |
| `dateTime` | `Jan 1, 2026, 8:00 AM` | `2026. 1. 1. 오전 8:00` |
| `integer` | `1,234` | `1,234` |

That is the design system's own rule transposed from CSS to formatting: *a
recurring per-page tweak is a new `cva` variant, not a `className` at the call
site.* Twelve screens cannot independently choose between a short date and a
medium one, and a closed set stays reviewable in a way that
`Intl.DateTimeFormatOptions` at each call site never is.

It wraps intlayer's formatters rather than `Intl` directly. They already inject
the locale and already cache their `Intl.*` instances — and a second cache in
`packages/core` would put an intlayer dependency in a package whose value is
that it has none. Keeping it out is what holds the blast radius of the i18n
decision inside `apps/web`, and why `packages/*` tests did not change.

`createFormatters` takes the locale explicitly and has no default. A unit test
supplies it rather than inheriting the machine's, which is the difference
between a test that fails in CI and one that fails only on someone's laptop.

## Dates

**No timezone is passed.** The user's wall clock is the frame they judge
"today" by.

This replaced `created.toISOString().slice(0, 10)`, which was wrong in a way
that had nothing to do with translation: `toISOString` renders the **UTC**
calendar day. A row created at `2026-01-01T23:00Z` showed as `2026-01-01` to
someone in `Asia/Seoul` whose wall clock said `2026-01-02 08:00`. Invisible to
anyone developing in UTC, and reproduced by the fixtures — `EPOCH + 16h` is
Jan 1 in UTC and Jan 2 in Seoul.

Determinism in tests is bought with Playwright's `timezoneId` and Vitest's
`TZ`, both pinned to `Asia/Seoul`, never by hardcoding a zone in the app.
**Seoul rather than UTC deliberately**: UTC is the one zone in which that bug
cannot reproduce, so pinning it would make the suite deterministic and the
regression test meaningless.

A rendered date is wrapped in `<time dateTime={iso}>`. That keeps the exact
instant in the DOM — which the ISO string was the only thing preserving — and
gives e2e a locale-independent selector.

`packages/core/src/proto/time.ts` stays locale-neutral. It is the one place a
proto `Timestamp` becomes a `Date`, and `toMillis` exists for sorting;
rendering lives here.

## Numbers

Formatted **before** they reach the dictionary:

```tsx
{c.range({ from: f.integer(from), to: f.integer(to), total: f.integer(total) })}
```

The interpolation's parameters are strings. If they were numbers the dictionary
would have to know the locale a second time, and the two could disagree.

`Intl.NumberFormat.prototype.formatRange` is tempting — it emits the locale's
own range separator — and is a trap here: when both ends are equal after
rounding it emits the *approximately* sign. `visibleRange` returns
`{ from: 0, to: 0 }` for an empty result, so the empty list would read
`~0–~0 of 0`. The en dash stays a piece of punctuation a translator owns.

A `<SelectItem>`'s **value** is a protocol token and stays `String(size)`;
only the **label** is formatted. `toPageSize` parses the value back with
`Number()`, and `Number("1,000")` is `NaN` — the day someone adds 1000 to
`PAGE_SIZE_OPTIONS`, a grouped value would make the picker silently inert.

## Plurals

There is no plural machinery, because nothing needs it — the copy avoids
plurals by construction, phrasing counts as ranges and the zero case as
"No items yet" rather than "0 items". That is a feature, not an accident.

**Never branch on a count in app code.** `count === 1 ? "1 item" : \`${n} items\``
is correct in English and wrong in Korean (no plural), Polish (four forms) and
Arabic (six). The formatting layer deliberately exposes **nothing that takes a
count and returns a word**, so reaching for the ternary means reaching outside
the seam, which is visible in review. A plural belongs in the dictionary —
intlayer ships `plural()` for it.

## Collation and normalization

Equality and ordering are the **server's** job, under a declared collation. The
client never re-sorts a server-ordered list, and there is no client-side sort
of a user-visible list anywhere in this app.

The mock server shows the contract:

- Uniqueness uses a module-scope `Intl.Collator` with `sensitivity: "accent"`.
  `toLowerCase() === toLowerCase()` fails twice: `"İ".toLowerCase()` is `i`
  plus a combining dot, which does not equal `i`; and NFD Hangul from macOS or
  an IME is not `===` to its NFC form, so two names that look identical both
  get created. ICU collation is normalization-insensitive, which settles the
  second for free. `"base"` would be too loose — it collides `resume` with
  `résumé`.
- Substring search normalises to NFC then folds case. `Intl.Collator` compares
  whole strings and cannot do containment, so there is no `Intl` answer.
  Turkish dotted/dotless İ still misses; a real backend should do this in the
  database (Postgres ICU, `citext`, `unaccent`).
- **Normalise to NFC on write.** The mock already documents that the server
  normalises by trimming; composing is the same class of thing, and doing it on
  write means every stored value is NFC and only the incoming query ever has to
  be.

## Direction

`LocaleProvider` writes `<html lang>` and `<html dir>`, and mounts Radix's
`DirectionProvider`.

**That provider is not redundant with `<html dir>`**, which is the part worth
knowing: Radix's `useDirection` resolves `localDir || globalDir || "ltr"` and
never reads the document. Without it every popper, select, dropdown and tooltip
computes left-to-right placement on a right-to-left page — the layout flips and
the menus do not.

`sonner` is the opposite: it reads `document.documentElement.dir` itself, so
the toaster needs nothing — which is also why the `dir` write must not be
"tidied away" as unused.

App code uses logical utilities (`text-end`, `border-e`). **`packages/design/src/ui/primitive/` does not**, and that is a documented gap
rather than an oversight: roughly 50 physical direction utilities across 19
files. Neither shipped locale is RTL, and a mechanical rewrite would be wrong
in at least two places a regex cannot see — `sheet.tsx`'s `side="right"` is a
prop shape, not a class, and `dropdown-menu.tsx`'s slide directions key off
Radix's `data-side`, which is already direction-resolved, so flipping the class
double-flips it. It would also be re-broken by the next `pnpm ui:add`.

**If an RTL locale ships**, that pass is the work, and it belongs in the
wrapper layer (`ui/<name>/<name>.tsx`) rather than in `primitive/`.

## Type

`--font-sans` and `--font-mono` in `inline.css` point at `--sans` / `--mono`,
whose values live in `light.css` beside `--radius`. The indirection is the
mechanism the colour tokens already use, and it is what makes two things
possible at once: an override in `app/theme.css`, and a per-language override.

Without it, `@theme inline` bakes the literal stack into every utility and both
overrides are silently dead — Tailwind emits no error, the utility just keeps
the old stack. Verify by inspecting the built CSS for `font-family: var(--sans)`.

The stacks append CJK families rather than prepending them: font matching is
per-character, so Latin still resolves at `ui-sans-serif` and only what the
earlier faces cannot draw falls through. `--mono`'s CJK entries are
**proportional**, and that is the trade — no system monospace carries CJK
glyphs, and a proportional glyph inside a monospace run beats a tofu box.

Han unification is the part one stack cannot settle: nothing in a font list
knows whether 直 should take Korean, Japanese or Simplified Chinese shapes.
`<html lang>` does, so the override goes on the variable:

```css
:root:lang(ja) { --sans: "Hiragino Sans", "Yu Gothic UI", Meiryo, …; }
```

Never `font-family` on a selector — that is the same disagreement between
`body` and the `font-sans` utility that `inline.css` already warns about.

`:lang(ko) { word-break: keep-all }` stops Korean breaking mid-word. It is
scoped on purpose: Japanese and Chinese have no inter-word spaces, so the same
rule there prevents breaking anywhere and the text overflows instead.

## Length

Translated text is longer. The rules that follow from that:

- A width that holds text is a **minimum** (`min-w-48 flex-1`), not a fixed
  `w-*`. A `w-*` is for a column of icons.
- `truncate` on **user content** is unrecoverable — one clipped line, no
  tooltip, and CJK packs about twice the information per character so the loss
  differs by language. The description cell uses `line-clamp-2` plus a `title`.
- `whitespace-normal` is required to beat the design package's global
  `whitespace-nowrap` on buttons, badges, table cells and select triggers.
