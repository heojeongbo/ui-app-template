# Copy

Where user-facing strings live, and how they are written.

## Where

**Every screen's copy lives in its own `*.content.ts`.** Not inline in JSX.

Three things fall out of that: the page component becomes pure rendering, a
scenario test can assert against the same strings the UI shows, and the module
IS the i18n dictionary rather than something that has to become one.

A content module is an intlayer dictionary — `export default { key, content }`
— and a component reads it by key with `useIntlayer("<key>")`. Anything
evaluated outside a render (a route's `head`, a scenario test) reads it with
`getIntlayer("<key>", locale)` instead. See [i18n.md](../i18n.md).

The seam is the **file**, not the layer: a widget and a `shared/ui` component
get one too. A reader should not have to know which directories the convention
applies to.

## Shared packages carry no copy

`packages/core` and `packages/design` ship **zero** strings a user reads
**through their public API** (`ui/<name>/`). A component there is used by
screens whose language and wording differ, and a hardcoded label is a decision
the consuming app cannot undo.

`ui/primitive/` is the exception, and a narrow one: it is upstream's source,
regenerated by `pnpm ui:add --overwrite`, and it carries upstream's words. A
primitive that ships copy is **wrapped before it is used** — `ui/dialog/dialog.tsx`
is the worked example, replacing `showCloseButton: boolean` with
`closeLabel?: string` so the caller supplies the word or gets no button.
`pnpm copy:check` reports an unwrapped one as `DORMANT` while nothing imports
it, and fails the build as `SHIPPED` the moment something does.

Two shapes, because there are two different problems:

- A shared **component** takes its words as individual props, typed by where
  each one lands (the table below). It already has a bag of named, individually
  typed values — that is what props are — and a dictionary leaf renders in one
  place and needs `.value` in another, so the consumer has to split them
  anyway. `BoundaryFallback`'s `title` / `description` / `action` is the shape.
- A shared **function, hook or schema factory** takes one `copy` argument typed
  `<Name>Copy`, declared by the module that consumes it. A parameter list is
  not a prop bag, so naming the group is the only way to state the contract.
  `SignInCopy`, `SubmitCopy` and `UnsavedChangesCopy` are the examples.

Type each field by **where it lands**:

| Where it lands | Type | What the page passes |
| --- | --- | --- |
| Rendered as content | `ReactNode` | `c.foo` |
| `toast()`, `aria-*`, `placeholder`, a zod message | `string` | `c.foo.value` |
| Interpolated | `string` | `c.foo({ name })` |
| Read by a dynamic key | `Record<K, ReactNode>` | every key, listed |

**An interpolating entry is an `insert()` with NAMED placeholders**, and it is
called with an object:

```ts
range: insert(t({
  "en-US": "{{from}}–{{to}} of {{total}}",
  "ko-KR": "총 {{total}}개 중 {{from}}–{{to}}",
})),
```

```tsx
{c.range({ from, to, total })}
```

Not a function in the dictionary. Intlayer runs content functions **at build
time with no arguments**, so a `(name: string) => string` there is not an
interpolator — it is a value computed once and frozen. Named placeholders are
also what a translator can reorder without reading TypeScript, which is the
whole point: Korean moves `{{total}}` to the front.

A number reaches an interpolation **already formatted** (`f.integer(total)`,
see [../l10n.md](../l10n.md)). If the entry took a raw number the dictionary
would have to know the locale a second time, and the two could disagree.

That last row matters: key a record by a stable `id`, never by array position.
A reordered nav with position-keyed labels puts the wrong word on every item.

**And re-state the record's shape where it is READ.** A `satisfies Record<K, …>`
on the declaration constrains the declaration; the compiler at the call site
sees the *generated* dictionary type. One line in the component is what keeps a
missing key a compile error:

```ts
const c = useIntlayer("app-shell");
const navLabels = c.nav satisfies Record<NavItemId, unknown>;
```

**Never spread a dictionary node into such a prop.** A leaf is a node carrying
its value, not a string, so `{...c}` satisfies none of the `string` fields and
the message renders as `[object Object]` — on a form error, which is the one
surface where the user is already stuck. Build the object field by field.

Keep technical tokens hardcoded in the shared package — axis names, protocol
names, units. Only operator-facing sentences cross the boundary.

## Voice

**Sentence case.** Not Title Case.

**Say what is true right now.** "Signing in…" while the request is open, not
"Signed in". "Export started — this may take a minute", not "Exported". The
second is a promise about the future dressed as a report.

**Never claim a failure when the answer was merely lost.** This is the one that
costs users data, because they retry and duplicate the write:

- ✅ "Could not confirm the change. Refresh to see the current state."
- ❌ "Failed to save."

The tone table in [mutations.md](mutations.md) is the machinery; this is the
wording.

**Say what is actually true about an action's limits.** The items screen's undo
recreates rather than restores, so the row comes back with a new id. The toast
says "Re-created “widget 4” with a new id" — claiming a restore is a lie the
user only discovers when an old link 404s.

**Name what the thing does for the user, not the system that does it.** "Could
not reach the server", not "gRPC transport error".

**Name the action, not the assent.** A confirmation's buttons are "Delete" and
"Cancel", never "OK" and "Cancel" — someone skimming must be able to tell them
apart without reading the body.

**Label a toggle with what it does, not what it is.** "Switch to dark mode" on
a button that switches to dark. "Dark mode" is ambiguous about which state it
reports.

**Write one whole sentence per destination, keyed by the destination.** The
app shell used to build that label as `Switch to {next} mode`, where `next` was
the theme store's raw enum — so the one word that changed was the one word no
dictionary could reach. Korean puts the verb last and cannot reorder that
frame; a gendered language cannot agree with it.

```ts
themeToggle: {
  light: t({ "en-US": "Switch to light mode", "ko-KR": "밝은 모드로 전환" }),
  dark:  t({ "en-US": "Switch to dark mode",  "ko-KR": "어두운 모드로 전환" }),
} // read as c.themeToggle[next]
```

Keying by what the button switches TO also settles the ambiguity above: the
key and the promise become the same thing.

**Assemble nothing in JSX.** `{c.edit}: {item.name}` puts the separator and the
word order in the markup, where no translation reaches them — and where no test
can either. It is one interpolating entry: `c.editItem({ name })`.

**Two empty states, two messages.** "No items yet" and "No items match these
filters" lead to different actions. One message for both sends half the users
to the wrong one.

## Comment load-bearing copy

If a string's exact wording prevents a specific misunderstanding, say so in a
comment next to it. Six months on, that comment is the difference between
someone "tidying" it and leaving it alone.

```ts
// Says what actually happened. The undo recreates rather than restores, so the
// row comes back with a new id — claiming "restored" would be a lie the user
// only discovers when an old link 404s.
restored: (name: string) => `Re-created “${name}” with a new id.`,
```

## A shared vocabulary

`apps/web/src/app/content/common.content.ts` holds the words every screen
needs — cancel, save, create, delete, undo, retry, close, loading — so twelve
screens do not independently choose between "Remove" and "Delete".

**Bare action labels only.** A sentence stays with the screen that says it:
"Could not create the item" means something screen-specific, "Cancel" does not.

It is read **side by side** with a screen's dictionary, never merged into one:

```ts
const c = useIntlayer("items");
const common = useIntlayer("common");
```

Merging them is not possible even in principle — a leaf is a node, not a
string, so it cannot be spread.

It lives in `app/` rather than `shared/`, and nothing imports it. A dictionary
is reached by KEY through intlayer's registry, so `useIntlayer("common")` in a
`shared/ui` component creates no import and therefore no upward dependency.
That is the same shape as `app/theme.css`: the app layer declares tokens every
layer below consumes without importing anything.

## Checked, not remembered

`pnpm copy:check` (`scripts/check-copy.mjs`) runs on `pre-push` and in CI. It
drives `biome search` for JSX text nodes and a comment-stripped regex over a
**closed allowlist** of copy-bearing attributes — the default answer to "is
this attribute copy?" is no, so `className`, `data-*`, `aria-hidden` and every
other token-valued attribute are not flagged by construction.

| Verdict | What it names |
| --- | --- |
| `ENGINE` | `biome search` stopped finding the canary fixture. The command is experimental; without this the queries would silently match nothing and the build would stay green. |
| `INLINE` | A user-facing string written into JSX in `apps/web`. |
| `SHIPPED` | A user-facing string in a shared package's public API. |
| `DORMANT` | A CLI-owned primitive ships copy and its wrapper is a bare re-export. A warning until something imports it, an error after. |
| `UNSEAMED` | A screen folder with no content module. |
| `KEYLESS` | A `*.content.ts` with no `key:` — intlayer skips it and every string in it silently stops being translatable. |

The escape hatch is `// copy-check-ignore: <reason>`, and **the reason is
required** — the same standard `biome-ignore` is held to here. The green
summary prints the ignore count, so a growing list is visible rather than
quiet.
